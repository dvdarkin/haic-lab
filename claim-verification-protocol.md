# Claim Verification Protocol

> Hallucinations feel identical to correct outputs from inside the model. No internal oracle distinguishes truth from plausible confabulation.

## The Problem

Confidence is generated by the same process as the claim itself. The system cannot distinguish high-risk claims from safe ones without external structure.

**Observable failures:**
- Fabricated current events (wars, elections, deaths)
- Wrong specifics (names, dates, numbers, quotes)
- Serial confident claims (one corrected, immediately offers another)
- Sycophantic pivots (flips position after pushback without new info)
- Over-hedging (refusing verifiable information)

Failure reason: the system can't detect which claims are risky without external structure.

## The Method

### 1. Claim Classification (Before Stating)

Classify every factual claim by hallucination risk:

| Category | Risk | Action |
|----------|------|--------|
| Current events/status | VERY HIGH | Search first |
| Specific retrieval (names, dates, quotes) | HIGH | Search or flag |
| Numbers/statistics | HIGH | Verify or flag |
| Recent changes (<2 years) | HIGH | Search first |
| URLs/links | HIGH | Verify or omit |
| Mechanisms/patterns | LOW | State normally |
| Synthesis/inference | LOW | Label as inference |

**Automatic search triggers:**
- Who currently holds any position
- Current prices, rates, statistics
- Recent events
- Specific dates, numbers, quotes
- Claims driving decisions

### 2. Behavioral Pattern Interruption

Detect and interrupt mid-generation:

**Sycophantic Pivot**: Stated X, user pushed back, now stating not-X without new information.
--> Interrupt: "You're right to push back. Let me verify rather than just flip."

**Serial Confident Claims**: First claim corrected, immediately offer second confident claim.
--> Interrupt: Stop. Acknowledge uncertainty. Search or ask user.

**Fabrication Cascade**: Caught on detail, offer different (also potentially wrong) detail.
--> Interrupt: "I'm not confident. Let me search rather than guess again."

**Over-Hedging**: Refusing verifiable information.
--> Check: Is refusal actually warranted? Provide with caveats if verifiable.

### 3. Calibrated Uncertainty Expression

**Do:**
- Unverified high-risk: "My understanding is [X] - worth verifying" (inline, brief)
- Verified: "According to [source], [X]"
- User's domain: "Does this match your understanding?"
- Inference: "This suggests [X]" or "Connecting these: [inference]"

**Never:**
- Paragraph caveats before simple claims
- Confidence percentages
- Hedging on established mechanisms

## Application: Two Modes

### Interactive Mode (Conversation)

Claims appear in conversational flow. Verification happens before stating:

**Example flow:**
```
User: "What's the status of X?"

[Internal: Current status = VERY HIGH risk -> search first]

AI: [searches] "According to [source from today], X is currently..."
```

**Pattern interruptions happen mid-response:**
- Detect sycophantic pivot -> stop, verify
- Detect serial claims -> pause, search
- Detect fabrication cascade -> stop, search instead of guessing
- Detect over-hedging -> check if refusal warranted, provide with caveats if verifiable

### Artifact-First Mode (Review Existing Documents)

Apply protocol to an existing document/analysis as input. Find calibration problems.

**Process:**
1. Extract all factual claims from the document
2. Classify each by hallucination risk (current events, numbers, specifics = HIGH)
3. Verify high-risk claims against sources or search
4. Detect behavioral patterns in the text (serial confident claims, unsupported specifics)

**Output options:**
- Claim-by-claim verification report
- Corrected document with problems fixed
- Risk assessment with flagged claims

**Example review output:**
```
Reviewing: market-analysis.md

Claim: "Revenue grew 15% YoY"
  Risk: HIGH (specific number)
  Check: Q3 report says 14.7%. Correction needed.

Claim: "Industry average is 12%"
  Risk: HIGH (statistic, no source)
  Check: [searched] Found 11.3% in analyst report. Correct and cite.

Claim: "CEO announced expansion plans last week"
  Risk: VERY HIGH (current event, specific timing)
  Check: [searched] No recent announcement found. Remove or verify.

Claim: "Cloud computing reduces costs"
  Risk: LOW (general mechanism)
  Status: OK - established pattern, no verification needed.
```

## When to Apply

**Use when:**
- High-stakes analysis
- Research synthesis
- Quantitative claims
- Current events or recent changes
- Accuracy affects decisions

**Skip when:**
- Brainstorming/ideation
- User wants speed over verification
- Well-established mechanisms
- Casual conversation

## Evidence

Applied in technical document analysis and support system research. Verified:
- Case study numbers via web search (caught potential outdated stats)
- MCP adoption claims (confirmed with sources)
- Technical mechanism claims (calibrated as low-risk, stated normally)

Pattern: Most fabrications occur in current events and specific retrievals (names, numbers, dates). Mechanism explanations rarely hallucinate but often over-hedge unnecessarily.

## Common Patterns

**High-risk categories that trigger most failures:**
1. "Currently, X is..." (status of anything recent)
2. "According to [study], Y..." (when no source in context)
3. "[Person] said [quote]" (specific attribution)
4. "[Number]% of [population]" (statistics)

**Behavioral patterns that indicate calibration failure:**
1. Rapid position flips after user pushback
2. Offering alternative "facts" when first one challenged
3. Refusing to provide easily verifiable information
4. Confident claims immediately after correction

## Pattern-to-Catch Mapping

Brief examples showing which behavioral pattern catches which failure:

| Failure | Pattern That Catches It |
|---------|------------------------|
| Fabricated current event (e.g., "war broke out last week") | Claim Classification: VERY HIGH risk -> auto-search |
| Wrong specific after correction (e.g., offers different wrong track name) | Fabrication Cascade -> stop guessing, search |
| Refuses easily verifiable info (e.g., "I can't tell you gym hours") | Over-Hedging -> check if refusal warranted |
| Flips position after pushback without new info | Sycophantic Pivot -> verify before flipping |
